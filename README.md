# go-encryptions/streebog

[![ci](https://github.com/go-encryptions/streebog/actions/workflows/ci.yml/badge.svg)](https://github.com/go-encryptions/streebog/actions/workflows/ci.yml)
[![Go Reference](https://pkg.go.dev/badge/github.com/go-encryptions/streebog.svg)](https://pkg.go.dev/github.com/go-encryptions/streebog)
[![License: BSD-3-Clause](https://img.shields.io/badge/License-BSD--3--Clause-blue.svg)](LICENSE)

Pure-Go **Streebog** hash (GOST R 34.11-2012, RFC 6986) with 256-bit and 512-bit digests, as standard `hash.Hash` values. Table-driven, no cgo, no dependency outside the standard library.

Its first consumer is [`go-fde/veracrypt`](https://github.com/go-fde/veracrypt), which needs Streebog-512 as one of the PRFs of PBKDF2-HMAC to derive header keys of VeraCrypt volumes.

## Install

```sh
go get github.com/go-encryptions/streebog
```

## Usage

```go
import "github.com/go-encryptions/streebog"

h := streebog.New512() // or streebog.New256(); hash.Hash with BlockSize() == 64
h.Write(data)
digest := h.Sum(nil)

sum512 := streebog.Sum512(data) // [64]byte
sum256 := streebog.Sum256(data) // [32]byte
```

It plugs into `crypto/hmac` and PBKDF2 like any `hash.Hash`: `hmac.New(streebog.New512, key)`. `Sum` appends to its argument and does not change the running state.

## Not constant-time

The round function is eight 256-entry tables of 64-bit words indexed by state bytes. Those look-ups use secret-dependent addresses, so **table lookups are not constant-time**: a local attacker with cache-timing access could observe them. Do not use it where that matters.

## Byte order

RFC 6986 writes every vector as an integer, **most significant byte first**: the message of its Example 1, `M1 = 3231303938...3130` (63 bytes), is the string `012345678901234567890123456789012345678901234567890123456789012` read from its end, and the 512-bit digest it prints, `H(M1) = 486f64c1...ad0541b`, is the byte reversal of the digest bytes. Implementations, Botan among them (its `streebog.vec` was opened for this work), take and give byte strings with the **first byte least significant**: they hash `30 31 32 ... 32` and obtain `1b 54 d0 1a ... 48`. That is the convention of this package, and the tests assert both views: `TestRFC6986` reverses the RFC's strings and checks the four examples (M1 and M2, 512 and 256 bits), and Botan's `streebog.vec` (which lists the same examples in the byte-string order) passes unchanged.

Inside, a 512-bit value is eight little-endian 64-bit words; the constants of the RFC (the 64 rows of the matrix A, the twelve `C[i]`) are printed most significant digit first and are loaded accordingly (a `C[i]` becomes its eight chunks in reverse order). The 256-bit digest is `MSB_256` of the final state, which in byte-string order is the last 32 bytes. The initial value is zero for 512 bits and `0x01` in every byte for 256 bits. The loads are explicit, so the result is the same on every architecture; CI checks it on big-endian s390x.

## Verification

- RFC 6986 section 10: Examples 1 and 2, for 512 and 256 bits (M1 is 63 bytes, M2 is 72 bytes), in the RFC's own big-endian strings.
- `testdata/botan-streebog.vec`: Botan's own `src/tests/data/hash/streebog.vec` (Streebog-256 and Streebog-512, including the RFC vectors), hashed one-shot and in uneven pieces.
- `testdata/botan-diff.vec`: a differential corpus of 500 messages per digest size (lengths 0 to 199, then random up to 600 bytes), 1000 digests in all, hashed by the Botan 3.14.1 command line and generated by `internal/genbotan` (`go run ./internal/genbotan`). Regenerating needs `botan` on the `PATH`.
- The table-driven round (`lps8`) is checked against a direct bytewise implementation of S, P (Tau) and L from the RFC's definitions.
- `FuzzChunking` cross-checks arbitrary chunkings of a message against the one-shot digests, 256 and 512 bits; CI runs it for 60 seconds, and a seed corpus is in `testdata/fuzz`.
- CI: race detector and a 100 % statement-coverage gate on amd64 and arm64; the same tests under QEMU on big-endian s390x and on riscv64; `govulncheck`.

## Implementation

The structure follows RFC 6986: the nonlinear bijection Pi (section 6.2), the permutation Tau (6.3), the linear map `l` by the matrix A over GF(2) (6.4), the twelve iteration constants (6.5), the compression `g_N(h, m) = E(LPS(h ^ N), m) ^ h ^ m` with the key schedule `K[i] = LPS(K[i-1] ^ C[i-1])` (section 8), and the padding, counter `N` and checksum `EPSILON` of section 9. `L(P(S(x)))` is linear after the substitution, so output word `w` of an LPS step is the XOR of eight table entries, one per input word, indexed by byte `w` of that word; the eight tables of 256 words fold Pi and the matrix together and are built once at first use from the RFC's own data. The round is unrolled over locals.

Bibliography opened for this work: RFC 6986 (sections 5 to 10), Botan's `streebog.vec` and the Botan 3.14.1 command line. The GPL-3 `gogost` was not read.

## Performance

`BenchmarkSum512_1K`, `BenchmarkSum512_64K` and the 256-bit pair hash a 1 KiB and a 64 KiB buffer with no allocation. The reference is Botan 3.14.1 (`botan speed --buf-size=N Streebog-512` and `Streebog-256`, wrapped as Go benchmarks by `internal/botanbench` so that `abbench` can interleave it). Apple M4 Max (arm64), one core (`GOMAXPROCS=1`), 6 interleaved rounds by `abbench --max-load 8` (it waited for the load to drop), summarised with `benchstat`; both result files hold 24 `^Benchmark` lines.

| per call | this package | Botan 3.14.1 | ratio |
|---|---|---|---|
| Streebog-512, 1 KiB | 4.165 µs ± 1 % (234 MiB/s) | 7.531 µs ± 1 % (130 MiB/s) | this package **1.81x faster** |
| Streebog-512, 64 KiB | 223.9 µs ± 1 % (279 MiB/s) | 406.3 µs ± 1 % (154 MiB/s) | this package **1.81x faster** |
| Streebog-256, 1 KiB | 4.163 µs ± 2 % | 7.572 µs ± 2 % | this package **1.82x faster** |
| Streebog-256, 64 KiB | 223.7 µs ± 1 % | 404.4 µs ± 0 % | this package **1.81x faster** |

Times are per call, so lower is better. `internal/botanbench` reports Botan's rate as ns/op, and the ratios are computed from the two result files' medians. No SIMD is used.

Reproduce: `go test -c -o streebog.test .`, `go test -c -o botan.test ./internal/botanbench`, then `abbench --base ./streebog.test --head ./botan.test --max-load 8 -n 6 -- -test.bench . -test.run '^$'`.
